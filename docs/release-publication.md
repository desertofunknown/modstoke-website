# Publishing product downloads

The current [`data/releases.json`](../data/releases.json) has no selected releases or files. `/release-index.json` is emitted with null `latest.manager` and `latest.loader` pointers, so the website shows an unavailable state. A screenshot, a source-tree prebuilt, or a local Loader preview is not a website release.

## Index contract

The static index has `schema: 1`, `latest: {manager, loader}`, and `releases: []`. Each non-null latest value is a `releaseId` of a reviewed record in `releases`. `channel` may be `stable` or `preview`; the selected pointer, not a version string comparison, defines current. Keep earlier verified records and bytes for rollback. Never replace bytes at a published versioned path.

Common release fields are `releaseId`, `product`, `version`, `channel`, `publishedUtc`, `sourceCommit`, `notesPath`, `validation`, and `artifacts`. Manager records have `defaultLoaderReleaseId`, which is `null` until a matching complete player bundle is ready. Loader records have `compatibility: {gameId, testedGameBuilds, minManagerVersion}` and `bundled: {sdk: {assemblyPath, sourceCommit}, client: {pluginId, version, installPath, sourceCommit}}`. The client component must be a separately built, tested companion; the current Admin DLL is not a client-only companion.

One artifact is supported per record. Manager uses `kind: "manager-windows"`; Loader uses `kind: "game-root-bundle"`. Its fields are `sitePath`, `fileName`, `size`, `sha256`, `signatureStatus`, and `signingEvidence`. `sitePath` must be `/downloads/{product}/{version}/{fileName}`. It is resolved against the index's HTTPS origin by a desktop client. Stable artifacts require `signatureStatus: "verified"` and `signingEvidence: {publisher, verifiedUtc, files: [{path, sha256, certificateThumbprint}]}`. A preview may instead use `signatureStatus: "unsigned-preview"`, `signingEvidence: null`, and a nonempty `unsignedReason`. The `signingEvidence` object records a release review; the site build does not perform Authenticode verification itself. An unsigned preview must never be described as signature verified.

`validation` records `cleanSource`, `licenses`, `build`, `install`, `game`, `multiplayer`, and `hostedFetch`. Clean source, license review, build, an isolated installation check, and fetch-back must be `passed` for both channels. Stable Loader game and multiplayer checks must also be `passed`. Preview Loader game and multiplayer may be `passed` or explicitly `pending`; `compatibility.testedGameBuilds` must be empty while game validation is pending, and nonempty only after a game check passes. Manager game and multiplayer checks may be `not-applicable`. These are human release attestations, not claims made by a successful website build. A preview with pending checks is a test build, not an accepted game or multiplayer release.

## Prepare a release

1. Build from a recorded clean source revision. Review included third-party licenses and notices. Test a fresh isolated install before either channel is selected. Stable Loader releases also need accepted game and multiplayer checks. For a preview, record unperformed game or multiplayer checks as `pending` and present that fact to downloaders. Verify signatures on publisher-controlled Windows binaries for a stable release; an unsigned preview must carry the explicit unsigned status and reason. The current dirty local Loader preview still fails the clean-source gate.
2. For Manager, choose **one** reviewed Windows package for the selected record: setup or portable. Add its final bytes under ignored `artifacts/hosted/manager/{version}/{fileName}`. For Loader, do not select a release until one game-root ZIP contains Loader, the SDK assemblies, and a distinct client companion. Put its final bytes under ignored `artifacts/hosted/loader/{version}/{fileName}`.
3. For a Loader record, add `data/loader-manifests/{releaseId}.json` from the final schema-1 per-file manifest. Its `files[]` must list every ZIP file and include the SDK assembly and client install paths. Keep `package.fileName`, `package.sha256`, `update.minManagerVersion`, and `version`; omit `package.downloadUrl` and `update.manifestUrl` because the build sets those from the deployment origin. Add `data/package-inventories/{releaseId}.json` with `{schema:1,releaseId,reviewedUtc,files:[{path,provenance,license,sourceRef,redistributionApproved:true}]}`. Every installed ZIP file needs one reviewed entry. `provenance` is `publisher` or `third-party`; record its actual license and source. The build uses Python 3 to compare every ZIP member's path, size and SHA-256 with the schema-1 manifest and to require complete provenance coverage. It also rejects obvious proprietary game-file paths. The human review must still confirm that no game files or files lacking redistribution rights are included.
4. Upload the final binary bytes to their immutable versioned website paths, fetch them back from the actual HTTPS host, and compare byte count and SHA-256. Only then mark `hostedFetch` passed. Do not mutate that URL afterward.
5. Complete the index record and latest pointer. For a Loader record, set `PUBLIC_ORIGIN` to the verified HTTPS site origin before building. Run `node --test`, `node scripts/build.mjs`, and `node scripts/http-qa.mjs`. The build refuses missing, symlinked, wrong-size or wrong-hash local artifacts. It copies only the records' verified files into `dist/downloads/` and emits `/release-index.json`.
6. Publish versioned files and manifests before the index and HTML that reference them. Re-fetch the public index and each selected file to confirm links and hashes. Keep older verified bytes available for rollback. The web server/CDN must apply the cache rules in [hosting notes](cache-and-deployment.md).

For a selected Loader release, the build emits both `/releases/loader/{version}/OpenACAILoader.manifest.json` and `/releases/loader/latest/OpenACAILoader.manifest.json`. They use the Loader's existing schema-1 `version`, `package.downloadUrl`, `package.sha256`, and `files[]` contract. The package URL points to immutable website-hosted ZIP bytes. No compatibility endpoint is emitted while `latest.loader` is null. Existing Manager installations that use an older GitHub URL require their own migration path; publishing this route does not redirect them.

The index and compatibility manifest are mutable JSON. A checksum inside either file detects a mismatched download but cannot independently authenticate the publisher. Manager must reject a hash or compatibility mismatch and should not report a complete player install when the client companion is absent.

## Release-page notes

The optional `changelog` string contains actual maintainer-written changes and known limitations. It is rendered as escaped plain text. If omitted or empty, the page explicitly says release notes have not been supplied; version, file and source metadata are not presented as a changelog. Each release has one history-section anchor. Current-download cards link to that section. Before activating an unsigned or game-pending preview, the page and Manager must visibly show `unsignedReason` and the pending checks. These are release attestations, not signature checks performed by the browser or proof that the update manifest is signed.
